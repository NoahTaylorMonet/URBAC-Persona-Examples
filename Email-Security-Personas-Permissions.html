Microsoft Defender for Office 365 · Unified RBAC

Email Security Personas & Unified RBAC Permissions

Common roles for managing email security, mapped to Microsoft Defender Unified RBAC (URBAC) permissions. Microsoft has been moving Defender for Office 365 Plan 2 organizations to URBAC as the default model on a rolling basis—on a slower timeline than Endpoint and Identity, so confirm under Permissions & roles whether your tenant is on URBAC or still on the legacy Email & collaboration roles before assigning anything below. Tasks outside URBAC scope (mail flow, message trace, PowerShell) fall back to Exchange Online RBAC, and those combinations are called out.

📄

Guidance only

These personas and permission mappings are illustrative examples, not a configuration baseline. They reflect Microsoft Learn documentation captured on 3 August 2026, they are static, and Microsoft's permission catalog, role names, and RBAC rollout change over time. Verify every permission against your own tenant before you assign it, and treat this page as a starting point rather than an authoritative source.

📌

What URBAC does and does not cover

Unified RBAC governs the Microsoft Defender portal at security.microsoft.com only. It does not apply to the Exchange admin center, the Microsoft Purview portal, or PowerShell, which use Exchange Online RBAC. Microsoft Entra roles such as Security Administrator always grant access regardless of URBAC activation.

4Where Unified RBAC and Exchange Online RBAC combine

Several features are configured in the Defender portal under URBAC, but the same action through PowerShell, mail flow, or a compliance workflow needs an Exchange Online or Purview role, because URBAC does not extend to PowerShell, the Exchange admin center, or the Purview portal. Plan both when a persona or an automation account works through cmdlets.

App-only automation shows the pattern

An unattended service that writes to the Tenant Allow/Block List authenticates app-only to Exchange Online and needs an Exchange RBAC role that can run the TABL cmdlets. URBAC does not apply to PowerShell, so a Defender portal permission alone will not authorize the write. A least-privilege option is a custom EXO role group limited to Get-/New-/Remove-TenantAllowBlockListItems, granted through Exchange.ManageAsApp, which avoids giving the app Security Administrator across the tenant.

6Best-practice notes

  • Build custom URBAC roles from specific permissions. Combine the exact permissions a persona needs (for example Security data basics + Alerts for a Tier-1 responder) instead of assigning a broad Entra role. This is the least-privilege path URBAC is designed for.
  • Entra roles override URBAC. Assigning Security Administrator in Microsoft Entra grants the underlying access regardless of URBAC activation, so it is broader than a scoped URBAC role. Reach for the URBAC permission when you want a tight boundary.
  • Configure your URBAC roles before activating URBAC. Once Unified RBAC is turned on, the older Email & collaboration roles page is no longer available, so import or map roles first.
  • Portal permission does not equal cmdlet permission. A persona with a URBAC permission can act in the Defender portal but still needs an Exchange Online role to run the equivalent PowerShell. If a scripted change fails with an access error, the missing piece is almost always an Exchange RBAC role.
  • Quarantine release is policy-gated. Even with E&C quarantine (manage), what a reviewer can release depends on the quarantine policy attached to each protection.
  • Elevate high-privilege roles just in time. Grant Security Administrator, Exchange Administrator, and Global Administrator through Microsoft Entra Privileged Identity Management (PIM) as time-boxed, approval-gated activations rather than standing assignments.
  • Keep dedicated break-glass accounts. Maintain at least two cloud-only emergency-access accounts excluded from Conditional Access, and reserve Global Administrator for them.
  • Prefer preset security policies. Microsoft recommends the Standard and Strict presets over hand-built policies for most tenants; they are managed under Core security settings (manage).
  • Separate duties and audit. Split policy configuration (Core security settings) from remediation approval (Response), and monitor changes to threat policies, TABL, transport rules, and connectors in the unified audit log.
